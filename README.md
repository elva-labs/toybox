# toybox

A small toolbox of games for the terminal. TypeScript, bundled with esbuild, no runtime dependencies.

## Install

```bash
brew tap elva-labs/elva
brew install toybox
```

## Run from source

```bash
npm install
npm start
```

`npm start` builds and launches the game menu. After a build you can also run `node dist/toybox.js`, or link it as `toybox` with `npm link`.

Everywhere: `q` or escape backs out one level, Ctrl-C quits.

## Games

### Sudoku

Pick a difficulty (easy 45 clues, medium 36, hard 30, expert 25). Every puzzle is generated fresh and has exactly one solution.

| Key | Action |
| --- | --- |
| arrows or `hjkl` | move the cursor |
| `1`-`9` | place a digit, or toggle a pencil mark in notes mode |
| `0`, space, backspace | clear the cell |
| `n` | toggle notes mode |
| `a` | fill pencil marks for every empty cell |
| `u` | undo |
| `H` | reveal the current cell |
| `N` | new game |

Givens are white, your entries cyan. An entry that does not match the solution turns red the moment you place it, so mistakes surface immediately. Cells holding pencil marks show a small circle, and the marks for the selected cell appear in the side panel. When the cursor sits on a digit, every other cell holding that digit turns yellow.

### Wordle

Six guesses at a five-letter word. Type letters, backspace deletes, enter submits. Green means right letter right place, yellow means right letter wrong place, and the keyboard below the grid tracks what you know. Repeated letters are marked by count, so guessing two E's against a word with one shows only one of them coloured.

`n` or enter starts another round once it ends. Escape goes back to the menu. Wordle is the one game with no `q` shortcut, since `q` has to stay typable.

The two word lists in `src/games/wordle/words.ts` have different jobs. `ANSWERS` is the pool a round is drawn from and is 714 hand-curated common words, so nobody has to guess something obscure. `ACCEPTED` is the guess list and is deliberately permissive, because rejecting a real word is far more annoying than allowing an odd one.

Both are generated by a script from the system dictionary. That dictionary holds no plurals or past tenses and predates words like `email`, so the generator derives them (`hill` to `hills`, `move` to `moved`, `ask` to `asked`) and adds a curated batch of everyday words on top.

### Solitaire

Klondike. The menu picks one card or three card draw and, if you want one, a deal number; leave it blank for any deal.

| Key | Action |
| --- | --- |
| arrows or `hjkl` | move the cursor |
| enter | take the card under the cursor, with its run, or drop what you are holding |
| space | draw from the deck, or turn the flip back over when the deck runs out |
| `1`-`7` | pick a tableau pile up, or drop on it |
| `0` or `f` | pick up the flip, the pile left of 1 |
| `a` | send the held card home, or -- holding nothing -- send everything that fits |
| `u` | undo |
| `N` | new deal |
| `r` | retry this deal |

Enter on the pile you are already holding from puts the cards back, so there is always a way to let go without escape, which the launcher wants for itself. `N`, `r` and `q` ask first once a run is under way; `y` or enter goes, `n` stays.

Cards are drawn as filled plates rather than as text on the background, so the board reads as objects on a table. A face up card carries its index in the top left and the mirrored index -- suit then rank -- in the bottom right, which is the rotational symmetry a real card's two indices have. Covered cards show their index row alone, so a pile is a stack. Backs are half block plates with a motif, and a run of them reads as ruled lines rather than pattern noise.

Two golds do the pointing. The bright one is the cursor and the darker one is what you are holding, and a card keeps its suit's colour under either, because the colour is what the next move is chosen by. When you are holding something, every pile that would take it lights up: its number turns gold and the card you would land on takes a green field.

Deals are numbered. The shuffle is seeded from the number, so a deal you liked -- or lost -- can be dealt again exactly, and `r` retries the one you are on. The clock starts on your first move and stops on the win, and a best time is kept for each draw mode, since a three card game is a different game.

Cards resize with the terminal. Three tiers, from 3x3 up to 7x5, chosen on rows as much as columns, because the tableau is what runs out of room first: a pile can reach nineteen cards, and there is no scrollback in the alternate screen to spill into. When a board is tighter than that, it gives ground in the order that costs the player least. The help lines go first, then the spacing, then the key hints. Only then do the piles compress, and they compress by collapsing their face down prefix to one counted rule -- a face down card is not playable, so nothing is lost by counting it -- before the top card loses height, and before any row is dropped. The frame never outgrows the terminal, so it never tears.

Suit glyphs are the one thing that can go wrong. `♠♥♦♣` are East Asian Ambiguous width: they are narrow in the terminals this is meant for, but a terminal running a CJK locale draws them double wide and shears the columns.

### Dino Run

The Chrome offline runner. Space or up jumps, down ducks, `r` restarts, `q` goes back.

Cacti on the ground, birds once you pass 150 points. High birds have to be ducked, low ones jumped. Night falls every 700 points and the stars come out. Your best score is saved.

It starts at 21 columns a second and climbs to 44 by about 2000 points, but speed is only part of it. The padding between obstacles shrinks from 12 columns to 5, the random spread on top of that shrinks from 26 to 6, and birds go from one obstacle in five to one in two. So the run keeps getting harder after the speed has capped. Spacing is always generated against the jump arc at the current speed, so a gap is never tighter than one jump can clear, however mean it gets.

Watch the background. Mesas are common, but there is an office out there with a lit sign, and after dark you might catch a saucer or a lambda burning up on its way in.

Runs at 50fps off the engine's tick loop. The field is drawn on a subcell canvas: every character holds a 2x2 grid of pixels rendered with quadrant block glyphs, so the dino, the obstacles and the ground all move in half character steps rather than jumping a whole cell at a time. Sprites are bitmaps where ink is exactly what collides, which keeps near misses honest.

Pacing is written in units per second in `src/games/dino/state.ts`, so changing `TICK_MS` changes the frame rate without changing how the game feels. Sprite sizes are load bearing: a wider dino takes longer to pass an obstacle than one jump can stay airborne, and low speed is the hard case because the obstacle crawls past while the dino comes down.

## Adding a game

A game is a directory under `src/games/` exporting a `GameModule`:

```ts
export const mygame: GameModule = {
  id: 'mygame',
  title: 'My Game',
  blurb: 'one line for the menu',
  start: (ctx) => ({
    render: () => 'the whole frame as one string',
    onKey: (key) => {
      if (key === 'q') ctx.exit();
    },
  }),
};
```

Register it in the `games` array in `src/main.ts` and it appears in the menu.

The runtime owns the terminal. It writes the frame your `render()` returns, so a game never writes to stdout itself. Keys repaint automatically. For animation, set `tickMs` and implement `onTick()`; the runtime drives the interval and repaints after each tick. `ctx.exit()` returns to the menu, and `dispose()` is called on the way out.

## Saving things

Anything worth keeping between sessions goes through `ctx.store`, which is scoped to the game's id:

```ts
interface Saved {
  best: number;
}

const saved = ctx.store.read<Saved>({ best: 0 });
ctx.store.write({ best: 4210 } satisfies Saved);
```

`read` takes the value to use when nothing has been saved yet, so a first run needs no special case. `write` replaces the whole value, so keep one object per game and put everything in it. Both are synchronous and cheap enough to call whenever a record changes.

Everything lands in one file, `~/.config/toybox/state.json` (or `$XDG_CONFIG_HOME`), with a key per game:

```json
{
  "dino": { "best": 4210 },
  "sudoku": { "best": { "easy": 91 } }
}
```

Games cannot read each other's keys. Saving is best effort: it is written to a temporary file and moved into place so a crash cannot truncate it, and if the home directory is read only the write is dropped rather than ending the game. Delete the file to reset everything.

## Layout

- `src/engine/types.ts` the game contract
- `src/engine/runtime.ts` terminal setup, input routing, tick loop
- `src/engine/launcher.ts` the game menu
- `src/engine/input.ts` key parsing
- `src/engine/ansi.ts` escape sequences and text helpers
- `src/games/<id>/` one directory per game
- `src/main.ts` the registry
